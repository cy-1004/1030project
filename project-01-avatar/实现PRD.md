# 产品一：虚拟人物形象设计展示 Demo 实现 PRD

版本：V1.1｜所属项目：虚拟人物形象设计展示软件｜独立入口：`http://<内网IP>:8101`｜共用后端：`backend/`｜项目目录：`project-01-avatar/`

**当前实现状态**：主展示区已升级为可拖动旋转的 3D 人物，支持部分面部参数、发型、服装与颜色调整；场景使用 1 张生成的展厅背景及 2 种程序化背景。首页和选项卡使用模型截图作为示意缩略图；鞋履暂提供两种真实模型，部分叠穿和侧面视角可能有穿插。后端采用 Python 标准库和 SQLite，目录数据目前内置于后端，作品记录保存形象配置。展示卡为 1600×900 PNG。模型来源与使用说明见本目录 `README.md`。

## 1. 目标与边界

让演示者在 2—3 分钟内完成一次“选人物 → 捏脸 → 换发型/服装/鞋履 → 换场景 → 保存并展示”的完整操作。观众应清楚看到形象和商品搭配实时变化，最终得到可回看的作品和可下载的展示卡。

这是浏览器 Demo：人物为可旋转的 3D 形象，部分脸部参数与搭配可编辑，数据可保存；不要求动捕、VRM/GLB 导出、商品库存或支付。页面中的“服装选购”只展示款式、颜色、尺码和搭配信息，不进入交易。

**当前验收范围**：首次访问即可开始操作；提供 3 个形象预设、6 个发型选项、6 套服装组合、2 款鞋履模型、3 组肤色、3 个展示背景；切换时显示加载状态；保存后重新打开仍能还原；展示卡可以下载为 PNG。

## 2. 演示对象与讲解路径

**主要用户**：服装品牌展示人员和形象设计人员。**观看者**：客户、验收人员或汇报会观众。默认按 1440×900 桌面大屏设计，兼容 1280×720 投屏和手机浏览器查看。

建议讲解路径：进入首页，点击“开始设计”；选择预设人物“都市漫游者”；打开“脸部”调节脸型与肤色；切换“发型”和“服装”，选一件大衣及颜色；切换鞋履；在“展示”中把背景改为时尚展厅；点击“保存作品”，进入作品详情，下载展示卡。整个过程不应出现登录、配置 Key 或等待外部模型生成的阻断步骤。

## 3. 信息架构与页面

| 页面 | 路由建议 | 主要内容 | 主操作 |
|---|---|---|---|
| 品牌首页 | `/` | 大幅人物主视觉、精选造型、三个预设入口、最近作品 | 开始设计、打开作品 |
| 编辑工作台 | `/studio/:id` | 左侧工具栏、中央人物舞台、右侧商品/参数面板、顶部作品操作栏 | 选预设、调脸、换装、换背景、保存 |
| 作品库 | `/works` | 作品卡片网格、搜索、筛选、创建时间和搭配摘要 | 打开、复制、重命名、删除 |
| 展示详情 | `/works/:id` | 全幅成品、服装/鞋履清单、搭配说明、背景切换 | 返回编辑、下载 PNG |

首次进入首页预置 3 张精选作品。若后端暂不可达，首页和编辑器仍可用本地演示数据打开；保存时显示明确错误提示，不能假装成功。

## 4. 编辑器详细需求

### 4.1 页面布局

桌面端采用三栏：左侧约 76 px 的垂直分类工具栏；中间占主要宽度的人物舞台；右侧约 340 px 的内容面板。顶部放作品名、撤销/重做、重置、保存、展示按钮。底部放视角切换（全身/半身）、舞台背景快捷选项和当前搭配摘要。分类切换不重置已选内容。

右侧面板根据分类切换：人物预设、脸部、肤色、发型、服装、鞋履、场景。素材卡包含缩略图、名称、风格标签和选中状态。服装卡可展开颜色与尺码；鞋履可切颜色。尺码只影响文案与视觉标签，不模拟真实物理合身效果。

### 4.2 可操作功能

| 功能 | 操作 | 可见反馈 | 保存内容 |
|---|---|---|---|
| 选人物 | 点击 3 个预设人物卡 | 人物基础脸部和体型变更 | `presetId` |
| 捏脸 | 脸型、眼距、鼻宽、嘴角四组滑杆，各 3—5 档 | 对应五官或轮廓平滑变化，显示当前档位 | `face` 参数 |
| 肤色 | 点击色卡 | 头、手、腿肤色同步变化 | `skinId` |
| 换发型 | 点击发型卡，必要时选发色 | 头发层立即更新，卡片选中 | `hairId`、`hairColor` |
| 换服装 | 点击服装卡，选颜色和尺码 | 上身/下身服装层更新，右侧显示单品介绍 | `outfitId`、`outfitColor`、`size` |
| 换鞋履 | 点击鞋履卡，选颜色 | 脚部造型更新 | `shoesId`、`shoesColor` |
| 换场景 | 选 3 个背景之一 | 人物不变，舞台光效/背景更新 | `sceneId` |
| 全身/半身 | 切换舞台视图 | 镜头平滑缩放，半身细节更清楚 | 仅编辑器临时状态 |
| 撤销/重做 | 点击按钮或快捷键 | 最近一步视觉状态恢复/重做 | 保存前本地状态栈 |
| 重置 | 二次确认后恢复该预设默认搭配 | 舞台及面板状态一致 | 当前草稿 |
| 保存作品 | 输入名称并保存 | 成功提示、作品库出现新卡片 | 完整配置及缩略图 |
| 下载展示卡 | 点击“下载 PNG” | 生成带人物、作品名与搭配摘要的图片 | 不必入库 |

### 4.3 状态细节

每次改动先更新画面，再异步更新草稿。保存按钮只在配置发生变化时突出显示。离开未保存作品时弹出提示。作品库中复制作品会生成新 ID，原作品不变。删除作品需二次确认。页面刷新后，已保存作品从后端恢复；未保存草稿可暂存在浏览器本地存储，方便演示中意外刷新后继续。

人物与服装的搭配不做复杂兼容矩阵。若某一服饰在某个预设上展示效果较差，素材制作时调整为统一锚点；前端不出现“不可穿戴”阻断状态。

## 5. 视觉设计与素材制作

**视觉关键词**：数字时装展厅、柔和聚光、高级材质、编辑工具的专业感。背景采用深石墨色，强调色可用冰蓝/暖金，面板为半透明深色卡；让人物和服饰始终比控件更醒目。主页为时尚大片式构图，编辑器更克制，作品页则适合投屏与截图。

**形象实现方式**：编辑舞台使用本地 GLB 人体、发型和服饰模型，由 Three.js 渲染；通过模型自带的形变参数调整脸型、眼距、鼻宽和嘴部宽度。服饰按人体区域遮挡处理并提供旋转观察，仍是演示级静态搭配，不承诺布料模拟或所有视角零穿插。背景素材保存在本地。

**首批素材清单**：3 个基础人物造型、6 款发型、6 款服装、6 款鞋履、3 张场景背景、3 张首页造型海报、每件单品一张缩略图。场景背景和海报优先用图像生成能力制作并放到 `assets/`，视觉风格统一；发型/服装/鞋履图层以透明 SVG/PNG 制作并在 3 个预设上逐一校对。所有素材用虚构品牌和人物，不使用未经授权的商标或真人肖像。

**交互质感**：分类切换 150—250 ms；人物换装使用短暂柔和过渡，避免闪白；按钮有悬停、选中、加载与成功状态；面板文字在投屏距离上可读。手机端改为人物舞台在上、分类横向滑动、素材抽屉在下，保证核心操作能完成。

前端视觉探索阶段使用 `huashu-design` 的网页/桌面原型模块：先依据本 PRD 做三个有明显区别的真实 HTML 初稿与截图，供用户选定方向；选定后再把设计实现为项目内可运行的 React 页面并接入后端。该技能的说明明确排除生产级、需要后端的系统，所以它只负责高保真原型和设计评审，不负责最终运行架构。原型须服从上述页面结构、实际交互与素材可对齐要求。

## 6. 前端与后端划分

前端独立放在 `project-01-avatar/frontend/`，使用 React + TypeScript + Vite，可参考 `tkmax-tools` 的组件结构和交互处理。开发端口与正式内网端口均明确配置为 `8101`，浏览器只访问这一地址。前端内的 `/api` 代理到共用后端 `http://127.0.0.1:8000`。六个项目不得共享同一前端构建产物。

共用后端中为本项目开设 `/api/avatar/*` 命名空间，处理商品目录读取、作品保存、作品列表与作品更新/删除。3D 渲染与 PNG 导出放在浏览器端，避免后端承担图像合成。使用 SQLite 表 `avatar_works` 保存作品；商品目录当前内置在后端。展示素材走静态文件，不经过模型实时生成。

| 接口 | 用途 | 关键字段 |
|---|---|---|
| `GET /api/avatar/catalog` | 获取人物、发型、服装、鞋履、场景目录 | 分类、ID、名称、颜色、缩略图路径 |
| `GET /api/avatar/works` | 获取作品列表 | ID、名称、缩略图、更新时间 |
| `POST /api/avatar/works` | 新建作品 | 名称、形象配置、缩略图 |
| `GET /api/avatar/works/{id}` | 打开作品 | 完整配置、创建/更新时间 |
| `PUT /api/avatar/works/{id}` | 保存现有作品 | 名称、形象配置、缩略图 |
| `POST /api/avatar/works/{id}/copy` | 复制作品 | 新作品 ID |
| `DELETE /api/avatar/works/{id}` | 删除作品 | 成功状态 |

作品配置建议采用固定结构：`presetId`、`face`、`skinId`、`hairId`、`hairColor`、`outfitId`、`outfitColor`、`size`、`shoesId`、`shoesColor`、`sceneId`。前后端都验证目录 ID 与颜色范围，避免无效配置打开空白舞台。后端只保存必要数据和缩略图路径；作品库卡片的其他信息可由目录映射得到。

## 7. 与 `tkmax-tools` 的复用边界

可参考现有 React/Vite 工程组织、图像上传/落盘方式、作品列表与任务反馈组件。现有 `digital_human.py` 是依赖外部数字人上游的视频合成代理，解决的是“音频 + 视频模板 → 口播视频”，不能直接用于人物捏脸与换装。产品一首版不调用 OpenRouter，不需要 API Key；后续若增加“根据文字生成展示海报”或“形象口播视频”，再分别接现有生图/数字人能力，并单列成本与等待提示。

## 8. 开发顺序与验收

1. 建立独立前端工程、路由和品牌首页，先让 `8101` 可访问。
2. 制作可对齐的 2D 人物图层与首批服装/发型/鞋履素材，完成编辑器即时预览。
3. 接入共用后端的目录和作品接口，完成保存、打开、复制、删除。
4. 完成展示页、PNG 导出、响应式布局和标准演示数据。
5. 用固定的 2—3 分钟讲解脚本走查：每一步都能看到变化，刷新后可恢复已保存作品，断网状态下核心流程仍可完成。

**验收场景 A**：新建人物，依次修改脸型、肤色、发型、服装颜色、鞋履和场景；每一步在舞台上有明显变化，右侧选中状态与画面一致。

**验收场景 B**：保存为“秋日城市漫游”，进入作品库打开；显示上次全部选择，复制后改装并保存，原作品不受影响。

**验收场景 C**：打开作品展示页，下载 PNG；图片包括完整人物、作品名、背景和搭配摘要，清晰度适合 1080p 投屏。

## 9. 仍需确认的问题与默认方案

| 问题 | 默认方案 |
|---|---|
| 人物风格希望偏写实、二次元，还是高级时装插画？ | 高级时装插画，兼顾可编辑性和展示质感 |
| 是否要放真实商品名称、价格和品牌？ | 先用虚构商品名与风格标签，不放价格 |
| 是否必须有 3D 旋转或口播视频？ | 首版不做；可用全身/半身视图和场景切换完成展示 |
| 是否要多人协作登录？ | 首版内网访客可操作，以作品名区分，不设账号 |
| 是否有既定品牌色、Logo、主视觉？ | 先设计独立的“Avatar Studio”演示品牌，后续可替换 |
| `huashu-design` 原型的三个视觉方向最终选哪一个？ | 原型阶段提交真实初稿后由用户选择，当前“数字时装展厅”仅是首选研究方向 |
