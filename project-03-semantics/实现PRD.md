# 产品三：智能语义理解 Demo 实现 PRD

版本 V1.1｜独立入口 `http://<内网IP>:8103`｜前端目录 `project-03-semantics/frontend/`｜共用 `backend/`

**当前进度**：用户选择 A「深蓝分析台」，正式 React 前端与共用后端已接通，8103 为正式 Demo 入口。三个设计初稿仍保留在 `design-demos/`。

## 目标与演示

让业务人员将一段文本转成易读的释义、实体与问答结果。默认演示：选择合同场景→载入合同样例→分析→点击高亮术语查看解释→针对合同期限提问→打开规则命中记录。提供客服、合同、研报三个场景，同一多义词随场景改变解释。

## 页面与操作

| 页面 | 功能 |
|---|---|
| 语义工作台 | 输入文本或选择样例，切换场景，显示流程开关、摘要、词语映射、实体定位、规则命中与转换文本；支持导出分析快照 |
| 文档问答 | 预设问题或自由提问，答案展示引用的原文片段，未找到依据时明确提示 |
| 术语与规则 | 词条增删改查、场景绑定、同义表达；规则增删改查、文字匹配、优先级、启停和版本；可返回工作台输入材料试验 |
| 处理记录 | 查询输入输出、规则命中和版本，支持回看及复跑 |

3 个文本样例、每个场景 10 个初始词条、2 条初始规则和 3 个预设问题。流水线展示“术语映射→规则转换→实体提取→摘要整理”及启停状态，不实现拖拽编排。切换场景保留输入以演示同词异义；载入样例才替换正文。正文、场景或流程改变后，旧结果不能直接用于问答，须重新分析。

## 数据与实现

共用后端 `/api/semantics/catalog`、`/terms`、`/rules`、`/analyze`、`/ask`、`/runs`；SQLite 记录词条、规则、问答和分析快照。沿用现有项目的 OpenRouter 配置和标准库请求方式。首版支持粘贴文本，文件上传作为可选增强。默认使用本地字典、原文摘录和关键词证据匹配，关闭模型辅助也能演示；开启后用模型整理摘要和回答，页面提示材料会发送至外部模型。引用必须逐字匹配原文，仍需人工核对答案。历史打开恢复分析结果，问答区可重新提问；重放应用当前词典与规则并另存记录。

## 视觉与验收

沿用 A 分析台的原文与结果并列布局。根据用户对「全是蓝色、对比度不高」的反馈，配色改为炭灰导航、浅灰工作区、白色阅读面板和深灰正文；绿色用于操作、选中术语，琥珀色用于引用定位。正文与标签的文字对比度按至少 4.5:1 检查。用原文高亮、场景释义、实体清单和可定位引用表达分析过程。移动端上下排布。验收：三个场景切换、同词不同释义、规则编辑后重跑结果变化、答案对应原文、历史记录可回看；无需外网即可演示本地案例。

## 默认决定与可后续补充的问题

按用户「都按默认来」执行：使用虚构合同、工单、研报；不增加登录、权限、文件上传或复杂编排；模型辅助默认关闭；后端沿用现有 `.env`。仍可后续补充：是否换成特定行业材料、是否需要 PDF 上传、是否让模型辅助默认开启。这些问题不影响本版演示交付。
